# 1.0.18-rc.1 compatibility validation

The source version is `1.0.18`; use the new tag `v1.0.18-rc.1` for candidate builds, following the release workflow's existing base-version convention. No tag or release is created by this change.

This candidate repairs release-runner CPU targeting and the macOS backend deployment target. Publish it as a new candidate; do not replace 1.0.17 assets.

## Automated gates

- CLI and desktop sidecars use the portable CPU policy. The configure test starts with stale optional CPU flags enabled and verifies they are forced off.
- Inspect executable architecture on all platforms and reject macOS executables requiring newer than macOS 11.
- Load an immutable tiny GGUF and generate tokens with each release backend before packaging. Linux executes this under QEMU's `qemu64` CPU without AVX.
- Exercise production startup and reviewed failure reporting in Chromium and WebKit. No diagnostic report is uploaded automatically.
- Retain the commit, tag and CPU policy alongside CLI artifacts and in native diagnostic reports.

## Required affected-device acceptance before stable promotion

These checks require the installed candidate, not a development server:

| Device | Check |
| --- | --- |
| Linux Mint, preferably without AVX2 | Install, download/load Gemma 3 1B, generate a reply; repeat using an existing model download. |
| Windows, preferably without AVX2 | Install, load Gemma 3 1B and Qwen 3.8 2B Distill, generate a reply. |
| Older Intel Mac | Record macOS version and Mac model/year; install, get past Starting, load a model and generate a reply. Verify on macOS 11 or the oldest supported OS available. |

Do not promote the candidate until these cases pass. QEMU and Mach-O header checks do not prove older macOS runtime/API compatibility, GPU compatibility, or correctness of the full model catalog.

On a failure, select **Review report**. Confirm version, target, OS, CPU features, failure stage and exit details; inspect the text before copying, downloading or opening a public GitHub issue. Include the model name and reproduction steps manually. Full paths, credentials and chat payloads must not be included. The last sanitized native report is retained locally so it can be reviewed after restart.

## Local verification recorded during implementation

An x86_64 backend rebuilt on Apple Silicon passed Mach-O architecture/minimum-OS checks and loaded/generated with the pinned tiny GGUF and the existing Gemma 3 270M model under Rosetta. Native tests, frontend unit tests, and Chromium/WebKit startup/report tests passed. This does not replace the affected-device acceptance above; Gemma 3 1B and Qwen 3.8 2B were unavailable locally.
